# うごき帳 — 設計

Astro の静的サイトを GitHub Pages（`/ugoki/`）で公開する。1作 = 1フォルダ（HTML・CSS・必要なら JS）にし、同じファイルを「デモとして動かす」と「コードとして見せる」の両方に使う。見せたコードと動いているコードが食い違わず、作品をポートフォリオや案件へそのまま移せる。

## 成功条件

1. 全作が、一覧のカードの枠と詳細ページの両方で動く（マウス・キーボード）。ホバーの動きは `@media (hover: hover)` の中に書き、タッチで貼り付かない
2. 画面切り替えの作を一覧の枠で動かしたあとでも、一覧↔詳細のページ間の動きが崩れない
3. 詳細ページのコードは、デモで動いているファイルそのもの
4. コピーしたコードは、このサイトのほかの CSS・JS に頼らず単体で動く
5. ホバーの動きは `:focus-visible` でも起きる
6. ライト既定・手動でダーク・選択を保存。再読み込みで一瞬ライトを経由しない
7. 幅 375px で横スクロールなし・コンソールエラー0件・`astro check` と build が通る

## 作品の作り方の決まり

- 動かすのは `transform`・`opacity`・`clip-path` だけ。レイアウトを動かさない
- 速さと緩急は CSS 先頭のカスタムプロパティ（`--duration` `--ease`）にまとめる。JS で動かす作も、JS がその値を読む
- 色は `light-dark()` で書く。サイトのテーマに追従し、コピー先でも `color-scheme` に追従する
- 視差効果を減らす設定でも動きは止めない（ユーザーの方針。各作のコードにもガードを入れない）

### スクロールの作

- JS ではなく CSS のスクロール連動（`animation-timeline: view()`）で書く。一番近いスクロール領域に自動で連動するので、一覧の小さな枠でも詳細ページでも同じコードで動く
- 未対応のブラウザは `animation-timeline` だけを無視し、時間で1回再生してしまう。そこで `animation` の宣言ごと `@supports (animation-timeline: view())` の中に入れ、`animation` の後に `animation-timeline` を書く。未対応なら最初から表示される
- 枠は上下の余白を 0 にする。先頭には「枠の中をスクロール」の案内（枠の高さ100%）、末尾には余白（60%）を置く。上下の余白を残すと、作品の頭が最初から枠の内側に入り、動きが始まらない
- 範囲は `cover` 基準で指定する。`entry` 基準だと、小さな枠では数十 px のスクロールで終わってしまう

### 画面切り替えの作

- `view-transition-name` を CSS に固定で書かない。JS が `startViewTransition` の直前に付け、終わったら外す。名前は文書全体で1つしか使えないため、固定で書くと一覧に複数置いたときに重複し、ページ間の遷移とも衝突する
- 名前は作のインスタンスごとに連番を付ける（`m-expand-0` など）
- `display` を指定した要素は `hidden` 属性だけでは消えないので、`[hidden] { display: none; }` を作の CSS に書く

### カルーセルの作

インジケーターの見た目は、スライドの横スクロールの量で決める。指で引けば引いた分だけ動き、点やボタンで送るときは `--duration` と `--ease` で動く。方式を選んだ理由は [002](decisions/002_carousel-scroll-linked-indicator.md)。

- スライドは `scroll-snap`（`x mandatory`・`scroll-snap-stop: always`）の横スクロールにする
- インジケーターの動きは Web Animations で作って止めておき、`scroll` のたびに `currentTime` をスクロールの割合に合わせる。キーフレームは1枚ごとに置き、緩急は付けない（linear）
- 点やボタンで送るときは、JS で `scrollLeft` を動かす。緩急は対象のない `KeyframeEffect` に `--ease` を渡し、その進み具合を毎フレーム読む。送る間は root に `.is-moving` を付けてスナップを外す。指・ホイール・キーが触れたら送りを止める
- 今の1枚（`aria-current`・矢印の `aria-disabled`）は、スクロール位置を四捨五入して決める
- 時間で満ちるバーは、指で触れている間と止めるボタン（`aria-pressed`）を押した間は時間を止める。スクロールが 150ms 止まったら、着いた1枚の時間を最初から数える
- 一覧の枠に収めるため、高さは スライド 140px＋操作部で 176〜180px にする

## サイト自体の動き

- 一覧 → 詳細は、ページをまたぐ View Transitions（`@view-transition { navigation: auto; }`）で、カードの枠が詳細の枠へ広がる
- 枠には `view-transition-name: stage-<slug>` を付け、動きは `view-transition-class: stage` でまとめて当てる。カードと詳細の枠は縦横比 4:3 でそろえる（比が違うと遷移中に中身がはみ出す）
- デモ内のリンクは押しても移動しない（`PieceStage.js` が止める）。コピー後のコードには止める仕組みは入らない

## 一覧のカード

- カード上部の枠に、その作のデモを実物のまま置く。カード全体はリンクにせず、下部の作品名が詳細へのリンク（デモの操作とぶつかるため）
- 枠の中身は、最も小さい枠（幅 375px の画面で 343×257px、余白を除いて高さ約 209px）に収める

## 表示まわり

- コードの色付けは Astro 標準の `<Code>`（ビルド時に色付け・実行時 JS なし）。github-light / github-dark をテーマで出し分ける
- 文字は `@fontsource-variable/noto-sans-jp` を自前で配信する
- テーマは `localStorage` の `ugoki:theme`。`public/theme.js` を head で同期読み込みして描画前に当てる
- ポートフォリオの規約に合わせる
  - BEM・接頭辞 m-/l-/u-/p-
  - `<style>` タグを使わず、CSS を隣接ファイルに置く
  - `<script>` では JS ファイルを import するだけ
  - `inlineStylesheets: 'never'`

## やらないこと

作り方の解説文・速さを変えるスライダー・検索や絞り込み・視差効果を減らす設定へのガード・Firefox 向けの代替 JS・オフライン表示・ポートフォリオへの組み込み（別の機会）。

## 実機での確認

- iPhone（Safari）: 合格（2026-10-19）。iPhone 14 Pro・iOS 26.6.1 で、6項目とも動いた。ユーザーの申告で、項目ごとではなく一括で「動いているのでOK」
  - 端末の「視差効果を減らす」はオンだった。それでも作品は動く。コードに prefers-reduced-motion の記述が無いため（「やらないこと」のガードにあたる。直すかは別に決める）
  - シミュレーター（iPhone 17・iOS 26.4）でも一覧を見た。6作が並び、横へのはみ出しは無い。タブの切り替えも動いた

## 未確認

- カルーセルの5作の実機（iPhone）での指操作。ヘッドレスの Chromium では、指の代わりに `scrollLeft` を動かして確かめた
- Firefox でのスクロール連動の対応状況
