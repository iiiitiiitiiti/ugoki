# 002. カルーセルのインジケーターは、止めた Web Animations をスクロール量で動かす

- 日付: 2026-10-21
- 対象: カルーセルの5作（囲みが移るドット・伸びるドット・伸び縮みして移るドット・時間で満ちるバー・数字が回る番号）

### 決定

インジケーターの動きを Web Animations で作って止めておき、スライドの `scroll` のたびに `currentTime` をスクロールの割合に合わせる。キーフレームは1枚ごとに置き、緩急は付けない。点やボタンで送るときは JS で `scrollLeft` を動かし、その動きに `--duration` と `--ease` を掛ける。送る間はスナップを外す。

### 背景

ユーザーの希望は「指に合わせて動く」こと（2026-10-21 回答）。指で引いた分だけインジケーターも動き、点で送るときはボタンのホバーのような ease-in-out で動いてほしい。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| CSS の `scroll-timeline` でインジケーターを動かす | Firefox では動かない。インジケーターはスライドの外にあるので `timeline-scope` も要るが、Safari の対応を確かめられていない |
| JS でスクロールの割合を `--progress` に書き、CSS の `calc()` で見た目を作る | 採用案に勝る点がない。作ごとに計算式を CSS に書くことになり、`clip-path` の補間も自分で書く |
| キーフレームに `--ease` の緩急を付ける | 複数枚を跳ぶと1枚ごとに速くなったり遅くなったりして脈打つ。点で送るときはスクロール側の緩急と二重に掛かり、指で引いたときは見た目が指より遅れる |
| 点で送るときに `scrollTo({ behavior: 'smooth' })` を使う | 速さと緩急がブラウザ任せになり、`--duration` と `--ease` で変えられない |

### 影響範囲

- 5作とも `script.js` が要る。JS が無いと、インジケーターは最初の1枚の見た目のまま止まる（スライドは指で送れる）
- 送る途中で指・ホイール・キーが触れたら、送りを止めてそちらに任せる
- 自動送りの時間は Web Animations で数える。指で触れている間と止めるボタンを押した間は止まる。時間で満ちるバー以外の作は、カーソルを載せている間も止まる（2026-10-21 に全作へ広げた）

### 検証

- 5作の詳細ページを、ヘッドレスの Chromium（Playwright）で操作した。点・矢印で3枚目へ送れる・矢印キーで1枚戻る・数字の矢印は続けて押すと2枚進む（2026-10-21）
- 時間で満ちるバー: 4秒で次へ送る・最後の1枚のあと先頭へ戻る・止めるボタンで時間が止まり押し直すと続きから満ちる・指で触れている間は止まる（2026-10-21）
- 自動送り（時間で満ちるバー以外の5作）: 4秒で次へ送る・カーソルを載せている間と止めるボタンを押した間は止まり、外すと続きから数える・最後の1枚のあと先頭へ戻る・点や矢印で送ると着いてから4秒を数え直す（2026-10-21・ビルド版をヘッドレスの Chromium で確認）
- 一覧で幅 375px と 1280px のとき横へのはみ出しなし。枠の高さ 176〜180px・ダークの表示・コンソールエラー0件（2026-10-21）
- 公開版で、送りが一瞬で終わり、バーが0.5秒ほどで次々に進んだ（2026-10-21 ユーザー報告）。公開用のビルドが `--duration: 600ms` を `.6s` に、`--interval: 4000ms` を `4s` に書き換え、JS の `parseFloat` が0.6ミリ秒・4ミリ秒と読んでいた。開発用サーバーでは書き換わらないので、上の検証では見えなかった。単位を見て換算する `toMs` に直し、ビルドしたものをヘッドレスの Chromium で確かめた。バーは4秒ごとに進み、点で送るとスライドが0.6秒かけて動く
- 実機の指操作と Firefox は未確認
