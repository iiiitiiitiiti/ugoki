# 006. ふわっと開く小窓は、作の中に重ねた role="dialog" で書く

- 日付: 2026-10-21
- 対象: 17作目「ふわっと開く小窓」（開閉の分類）

### 決定

作の root を小さなページの模型にし、その上に背景の膜と小窓（`role="dialog"` と `aria-labelledby`）を重ねる。開閉は root の `.is-open` で切り替え、動きは CSS の `transition` で書く。小窓は `scale: 0.92` と `translate: 0 8px` から広がって現れ、膜は `opacity` で暗くなる。閉じるときは開くときの 0.6 倍の時間で引かせる。

開いている間は後ろのページ部分を `inert` にして、小窓へフォーカスを移す。Esc・膜のクリック・閉じるボタンで閉じ、開いたボタンへフォーカスを戻す。書き方は ×に変わるメニューボタン（[003](003_toggle-menu-button.md)）にそろえた。

### 背景

ユーザー依頼「案4のふわっと開く小窓を作ってください」（2026-10-21）。案は `DESIGN.md` の「追加案」の4番で、承認済みの説明は「少し縮んだ状態から広がり、背景が暗くなる。枠の中で開く」。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| `<dialog>` を `showModal()` で開く | 小窓と `::backdrop` が最前面の層に出て、枠の外のサイト全体を覆う。「枠の中で開く」に反し、一覧に並ぶ他の作も隠れる |
| `<dialog>` を `show()` で開き、`@starting-style` と `transition-behavior: allow-discrete` で動かす | 非モーダルなので Esc で閉じず、後ろの `inert` も自前で要る。得るものが少なく、既存の開閉の作と書き方がずれる |
| `aria-modal="true"` を付ける | 読み上げに「外側は無い」と伝える属性。後ろを `inert` にするのは作の中だけで、Tab でサイトの他の部分へ出られる。読み上げとキーボードの扱いが食い違う |

実際のサイトでページ全体を覆う小窓にするなら、`<dialog>` の `showModal()` を使う。そのときは外側が自動で操作できなくなるので、`aria-modal` も成り立つ。

### 影響範囲

- 閉じている膜と小窓は透明でも枠を覆うので、`pointer-events: none` で開くボタンへのクリックを通す
- 閉じるときは後ろの `inert` を外してから、ボタンへフォーカスを戻す。逆の順だとフォーカスが戻らない
- 見出しの id は JS で連番を付ける。一覧と詳細で同じ作が複数出ても重ならない
- 方式は別モデル（fable-advisor）と壁打ちして決めた。`aria-modal` を外す・クリックを通すなどの指摘を反映した

### 検証

- 本番ビルドで、詳細ページと一覧（幅 375px・ライト・ダーク）の3か所とも同じ動きになった。開いて 0.08 秒後は小窓の不透明度 0.7 前後で広がる途中、0.7 秒後は不透明度・`scale` とも 1（2026-10-21）
- 開くと小窓へ、Tab で閉じるボタンへフォーカスが移る。Esc・膜のクリック・閉じるボタンのどれでも閉じ、開いたボタンへフォーカスが戻る（2026-10-21）
- 幅 375px で横スクロールなし。作の大きさ 295×176px に対し、小窓はその内側に収まる。コンソールエラー0件・`astro check` 0件（2026-10-21）
