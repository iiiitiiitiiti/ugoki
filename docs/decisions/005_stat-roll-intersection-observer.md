# 005. 数字が回って止まる実績表示は、見えたら時間で回す（IntersectionObserver）

- 日付: 2026-10-21
- 対象: 16作目「数字が回って止まる実績表示」（スクロールの分類）

### 決定

実績の数字を桁ごとの帯（0〜9 を2周）にし、帯の `translate` を Web Animations で動かす。作が枠に6割入ったら、時間（`--duration`）で回して左の桁から止める。枠から出きったら0に戻し、もう一度入ったらまた回す。見えたかどうかは `root` を指定しない IntersectionObserver で見る。

スクロールの作は CSS の `animation-timeline: view()` で書く決まり（[001](001_astro-one-folder-per-piece.md)）だが、この作はその例外にする。スクロール量に合わせて動く作ではなく、見えたのを合図に時間で動く作だからである。

### 背景

ユーザー依頼「案3の数字が回って止まる実績表示を作ってください」（2026-10-21）。案は `DESIGN.md` の「追加案」の3番で、承認済みの説明は「見えたところで回って止まる」。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| CSS の `animation-timeline: view()` でスクロール量に合わせて回す | スクロールを途中で止めると、数字も途中の値（例: 0,640）で止まる。実績の数字が違う値で見えるのは誤解を招く。桁ごとの帯を CSS だけで組むと HTML も長くなる |
| JS で数を数え上げる（0→1,200 を毎フレーム書き換える） | 文字を書き換え続けると読み上げが乱れ、幅も揺れる。スロットのように回る見た目にもならない |
| 枠の上端に戻っても0に戻さない | 一覧で見直したときに動きが見えない。見本帳なので何度でも見られるようにする |

[001](001_astro-one-folder-per-piece.md) が IntersectionObserver を退けた理由は「一覧の枠と詳細ページで監視する領域が変わり、書き分けが要る」だった。`root` を指定しなければ、交差は画面に対して計られ、途中のスクロール領域（一覧の枠）の外は切り取られる。そのため同じコードで一覧と詳細の両方が動き、この理由は当たらない。スクロール量に合わせて動く作は、これまでどおり `view()` で書く。

### 影響範囲

- 作の名前は `stat-roll`。`count-roll` はカルーセルの「数字が回る番号」が使っている
- 枠の端にぴったり接した状態は、交差しているのに割合が0になる。割合0.3から端に接した0へ移っても、しきい値0をまたがないので通知が来ない。そこでしきい値へ 0.01 を足し、割合が 0.01 を下回ったら0へ戻す
- 読み上げには元の数字（1,200 など）を1回だけ渡し、帯の数字は `aria-hidden` にする。JS が動かなければ元の数字がそのまま見える

### 検証

- 本番ビルドで、詳細ページと一覧（幅 375px・ライト・ダーク）の3か所とも同じ値になった。入る前 0,000 / 00 / 00、0.4秒後は回っている途中、2.4秒後 1,200 / 98 / 36（2026-10-21）
- 一覧の枠を先頭へ戻すと 0,000 に戻り、もう一度入ると 1,200 まで回った（2026-10-21）
- 幅 375px で横スクロールなし・作の高さ 89px（上限 209px）・コンソールエラー0件・`astro check` 0件（2026-10-21）
