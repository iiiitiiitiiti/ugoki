# 003. 「開閉」の分類を足し、1作目は×に変わるメニューボタンにする

- 日付: 2026-10-21
- 対象: 13作目の題材と、新しい分類「開閉」

### 決定

押すたびに開いて閉じる部品の分類「開閉」を足す。1作目は、3本線が中央に集まってから×に回るメニューボタンにする。メニューはページの上に重ね、`clip-path: inset()` で上から開く。項目は1つずつ遅れて入る。

### 背景

ユーザー依頼「あなたのおすすめで動きを追加してください」（2026-10-21）。題材の選定は任された。これまでの12作には「押して開き、もう一度押して閉じる」部品が無い。スマホ表示のメニューボタンは、案件のサイトでほぼ毎回作る。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| 開閉するアコーディオン（よくある質問） | 中身の高さを動かすことになり、「レイアウトを動かさない」決まりに反する。高さを変えずに見せると、閉じた行の下に空きが残る |
| 画面全体を覆うメニュー | 一覧の小さな枠では、覆う動きと普通の開閉の違いが見えにくい |
| 既存の分類（画面切り替え）に入れる | 画面切り替えの作は View Transitions で書く決まり。メニューボタンは CSS の `transition` で足りる |

### 影響範囲

- 分類は「ホバー・スクロール・画面切り替え・開閉・カルーセル」の順に並ぶ
- 線の2段の動きは `transform` ではなく個別の `translate`・`rotate` で書く。どちらも transform の仲間で、レイアウトは動かさない

### 検証

- 本番ビルドで、開くと線が集まってから回り（約200ms ずつ）、閉じると逆の順に戻ることを値で確かめた。`aria-expanded` と読み上げ名が切り替わる（2026-10-21）
- 開くとリンクへ Tab で移れ、閉じている間は移れない。Esc で閉じるとボタンへ戻る（2026-10-21）
- 幅 375px で横スクロールなし・枠の高さ 176px（上限 209px）・ダークの表示・コンソールエラー0件・`astro check` 0件（2026-10-21）
