# 001. Astro の静的サイトにし、1作を1フォルダの素の HTML・CSS・JS で持つ

- 日付: 2026-10-19
- 対象: サイト全体の構成と、作品の持ち方

### 決定

ポートフォリオと同じ Astro で静的サイトを作り、GitHub Pages で公開する。作品は `src/pieces/<slug>/` に素の HTML・CSS・JS で置き、同じファイルをデモとしても、詳細ページのコードとしても使う。スクロールの動きは CSS のスクロール連動で書く。

### 背景

Web 制作の仕事で流用し、転職用ポートフォリオの部品にもする動きの見本帳がほしい。1作の中身は「触って試せる動き＋コピーできるコード」（ユーザー回答 2026-10-19）。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| Vite + React（ひとつめ・がまんログと同じ） | 見せるコードが JSX になり、案件の素の HTML・CSS へ流用しにくい |
| ビルドなしの HTML を1作1枚 | 色付きのコード表示と一覧を手で保つことになり、見せるコードと動くコードがずれやすい |
| CodePen に置いて埋め込む | 外部サービスの読み込みが遅く、自分のサイトとして見せられない |
| スクロールの動きを IntersectionObserver（JS）で書く | 一覧の小さな枠と詳細ページで監視する領域が変わり、作ごとに書き分けが要る。CSS なら一番近いスクロール領域に自動で連動する |
| 画面切り替えの作の `view-transition-name` を CSS に固定で書く | 名前は文書全体で1つだけ。一覧に並べると重複して動かず、ページ間の遷移とも衝突する |

### 影響範囲

- 作品の CSS・JS はサイトのほかのファイルに頼らない。作を足すときも、コピーして単体で動くことを守る
- スクロール連動に対応していないブラウザでは、スクロールの作は最初から表示されたままになる
